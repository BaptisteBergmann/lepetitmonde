# Polls on posts ("sondage")

## Context

Feature request: let a post carry an optional lightweight poll — e.g. a photo from an apple-picking outing with the question "Who do you think ate the most apples?" and a few free-text options people vote on. This is explicitly **not** related to the existing `/baby/[babyId]/guess` "pronostic" game (guess_questions/guesses tables — private, single immutable guess per user, admin-moderated proposals, no results reveal). The new feature is the opposite in spirit: public, live, re-votable, no moderation.

Confirmed decisions (asked via AskUserQuestion):
1. Options are free-text, typed by the post author (2-6 per poll) — not restricted to picking real family members.
2. Voting is re-votable (upsert), mirroring `post_reactions`' `UNIQUE(post_id, user_id)` pattern.
3. Vote tallies are always visible live to anyone who can see the post — no "vote first to unlock results" gating.

Design deviates from the literal `guess_questions.options jsonb {choices:[]}` shape in one way: poll options are stored as their own normalized `poll_options` table (not jsonb), so each vote can FK a real option row. This gives referential integrity and lets tallying be a plain join/count instead of app-level array-index bookkeeping — worth the small extra table.

## Database (no RLS — this project has none anywhere; all access control is in `src/utils/actions/*`, matching `assertIsAdmin`/`getUserAccess` patterns already used for posts)

New migration, created via `mise run db_migration_new create_polls`, styled exactly like `supabase/migrations/20260721200201_create_posts.sql` (double-quoted identifiers, explicit `ALTER TABLE ... ADD CONSTRAINT`, one `GRANT ALL ... TO anon/authenticated/service_role` block per table):

```sql
-- Polls: optional, zero-or-one per post. question is distinct from posts.caption.
-- UNIQUE(post_id) enforces at most one poll per post without a nullable column on posts.
CREATE TABLE "public"."polls" (
  "id" uuid DEFAULT gen_random_uuid() NOT NULL,
  "post_id" uuid NOT NULL,
  "created_by" uuid DEFAULT auth.uid() NOT NULL,
  "question" character varying NOT NULL,
  "created_at" timestamptz DEFAULT now() NOT NULL
);
ALTER TABLE "public"."polls" OWNER TO "postgres";
ALTER TABLE ONLY "public"."polls" ADD CONSTRAINT "polls_pkey" PRIMARY KEY ("id");
ALTER TABLE ONLY "public"."polls" ADD CONSTRAINT "polls_post_id_key" UNIQUE ("post_id");
ALTER TABLE ONLY "public"."polls" ADD CONSTRAINT "polls_post_id_fkey" FOREIGN KEY ("post_id") REFERENCES "public"."posts"("id") ON DELETE CASCADE;
ALTER TABLE ONLY "public"."polls" ADD CONSTRAINT "polls_created_by_fkey" FOREIGN KEY ("created_by") REFERENCES "public"."users"("id") ON DELETE SET NULL;
GRANT ALL ON TABLE "public"."polls" TO "anon";
GRANT ALL ON TABLE "public"."polls" TO "authenticated";
GRANT ALL ON TABLE "public"."polls" TO "service_role";

-- Free-text options, 2-6 per poll (enforced in the server action, not the DB).
CREATE TABLE "public"."poll_options" (
  "id" uuid DEFAULT gen_random_uuid() NOT NULL,
  "poll_id" uuid NOT NULL,
  "label" character varying NOT NULL,
  "position" integer DEFAULT 0 NOT NULL
);
ALTER TABLE "public"."poll_options" OWNER TO "postgres";
ALTER TABLE ONLY "public"."poll_options" ADD CONSTRAINT "poll_options_pkey" PRIMARY KEY ("id");
ALTER TABLE ONLY "public"."poll_options" ADD CONSTRAINT "poll_options_poll_id_fkey" FOREIGN KEY ("poll_id") REFERENCES "public"."polls"("id") ON DELETE CASCADE;
GRANT ALL ON TABLE "public"."poll_options" TO "anon";
GRANT ALL ON TABLE "public"."poll_options" TO "authenticated";
GRANT ALL ON TABLE "public"."poll_options" TO "service_role";

-- One active vote per user per poll; re-votable via upsert on (poll_id, user_id),
-- same shape as post_reactions' UNIQUE(post_id, user_id).
CREATE TABLE "public"."poll_votes" (
  "id" bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
  "poll_id" uuid NOT NULL,
  "option_id" uuid NOT NULL,
  "user_id" uuid DEFAULT auth.uid() NOT NULL,
  "created_at" timestamptz DEFAULT now() NOT NULL
);
ALTER TABLE "public"."poll_votes" OWNER TO "postgres";
ALTER TABLE ONLY "public"."poll_votes" ADD CONSTRAINT "poll_votes_pkey" PRIMARY KEY ("id");
ALTER TABLE ONLY "public"."poll_votes" ADD CONSTRAINT "poll_votes_poll_id_user_id_key" UNIQUE ("poll_id", "user_id");
ALTER TABLE ONLY "public"."poll_votes" ADD CONSTRAINT "poll_votes_poll_id_fkey" FOREIGN KEY ("poll_id") REFERENCES "public"."polls"("id") ON DELETE CASCADE;
ALTER TABLE ONLY "public"."poll_votes" ADD CONSTRAINT "poll_votes_option_id_fkey" FOREIGN KEY ("option_id") REFERENCES "public"."poll_options"("id") ON DELETE CASCADE;
ALTER TABLE ONLY "public"."poll_votes" ADD CONSTRAINT "poll_votes_user_id_fkey" FOREIGN KEY ("user_id") REFERENCES "public"."users"("id") ON DELETE CASCADE;
GRANT ALL ON TABLE "public"."poll_votes" TO "anon";
GRANT ALL ON TABLE "public"."poll_votes" TO "authenticated";
GRANT ALL ON TABLE "public"."poll_votes" TO "service_role";
```

No `notification_type` enum change: a poll is just an attribute of a post, and posts already fire `new_post` on creation. Adding a vote-by-vote notification would be spammy for a running tally, so **no notification on `votePoll`** either.

## Server actions — new file `src/utils/actions/polls.ts`

Follow the exact template already used in `posts.ts`/`reactions.ts`: `'use server'`, `createClient()`, `contextLogger = logger.child({ function: fn.name, ...ids })`, `getAuthUser()`, throw `new Error("Non autorisé")` when unauthenticated, `contextLogger.error(error, "...")` + rethrow on Supabase errors, `revalidatePath('/baby/${babyId}/feed')` after mutations.

- `createPoll(postId, babyId, question, options: string[])` — `assertIsAdmin(supabase, babyId)`; validate `2 <= options.length <= 6` (throw a French error otherwise); insert `polls` row then `poll_options` rows (`position` = array index). Called as a follow-up step in `create_post_modal.tsx`'s `handleConfirm`, right alongside the existing `attachPostPhotos` follow-up call after `createPost`.
- `updatePoll(pollId, postId, babyId, question, options: string[])` — `assertIsAdmin`; if `poll_votes` already exist for this poll, reject with `"Impossible de modifier un sondage ayant déjà des votes"` (mirrors `guess_questions.updateQuestion`'s existing "blocked once answered" precedent) — otherwise update `question`, delete + re-insert `poll_options`.
- `deletePoll(pollId, babyId)` — `assertIsAdmin`; deletes the poll row (cascades). Used when an existing poll is removed from a post via the edit modal.
- `votePoll(pollId, babyId, optionId)` — any authenticated user, no admin check (matches how `addReaction`/`addComment` don't re-verify post visibility server-side either — visibility is a read-time filter, not re-checked on write). `supabase.from('poll_votes').upsert([{poll_id, option_id, user_id}], { onConflict: 'poll_id,user_id' })`. `revalidatePath`. No notification.
- `getPollWithResults(postId): Promise<PollWithResults | null>` — single query `polls.select('*, poll_options(*, poll_votes(user_id, users(*)))').eq('post_id', postId).maybeSingle()`, shaped via `getDisplayName()` (from `src/utils/users.ts`) exactly like `getReactions`'s `namesByEmoji` construction. Returns `null` if the post has no poll.

```ts
export type PollWithResults = {
  id: string
  question: string
  totalVotes: number
  myOptionId: string | null
  options: { id: string; label: string; count: number; voterNames: string[] }[]
}
```

Fetch pattern: **per-card client fetch**, not batched into `getPosts`. Reactions and comments already fetch per-card client-side (`useEffect` in `PostCard` calling `getReactions`/`getComments`) despite being N+1 across a feed page — polls following the same precedent is consistent and simpler than extending `PostWithDetails`/`getPosts`/`toPostWithDetails`. No realtime needed; refetch after voting like `ReactionPicker` does.

## UI

- **New `src/app/baby/[babyId]/feed/_components/poll_voter.tsx`** (client), modeled on `reaction_picker.tsx`: fetches `getPollWithResults(post.id)` on mount, renders `null` if no poll. Otherwise renders the question, then each option as a clickable full-width row with a percentage bar (`count/totalVotes`) and vote count, highlighted if it's `myOptionId`; clicking calls `votePoll` then refetches. Reuse the `Popover` names-list pattern from `ReactionPill` so tapping a count shows `voterNames`. Wrap the whole thing in its own `rounded-2xl border border-landing-border p-3` block so it reads as a sub-card.
- **`post_card.tsx`**: mount `<PollVoter postId={post.id} babyId={babyId} />` between `<ReactionPicker />` and the comments section.
- **`create_post_modal.tsx`**: add a "Ajouter un sondage" toggle revealing a question textarea + 2-6 option inputs (add/remove-option buttons, remove disabled at 2, add disabled at 6). In `handleConfirm`, after `createPost` succeeds, if enabled and valid: `await createPoll(postId, babyId, question.trim(), options.map(o => o.trim()).filter(Boolean))`. Disable "Publier" if the poll is enabled but invalid (empty question or <2 non-empty options).
- **`edit_post_modal.tsx`**: same fields, pre-seeded by fetching `getPollWithResults(post.id)` on mount (client-side, consistent with the per-card fetch decision — do not thread poll data through `PostWithDetails`). On confirm: existing poll + still enabled → `updatePoll`; existing poll + cleared → `deletePoll`; no poll + now enabled → `createPoll`.

## Verification

No automated test suite exists in this repo (`package.json` scripts are `dev`/`build`/`start`/`lint`/`typecheck` only) — verify via typecheck/lint + manual pass:

1. `mise run db_migration_new create_polls`, fill in the SQL above, then `mise exec -- pnpm supabase db push` (per CLAUDE.md, run outside a predefined mise task with `mise exec --` so the `[env]` block is injected) — or `mise run db_push` directly since it's a predefined task.
2. `mise run update_types` to regenerate `database.types.ts`.
3. `pnpm run typecheck` and `pnpm run lint`.
4. Manual test in the running dev server (use the `run` skill):
   - Create a post as admin with a 2-option poll, no photo — confirm it renders with 0 votes on each option.
   - Try to add a 7th option — confirm the button disables at 6; try submitting with 1 option — confirm it's blocked client-side.
   - Vote as a non-admin member with visibility on the post — confirm the tally/percentage bar updates and switching your vote moves it (not duplicated).
   - Confirm a member without circle access to the post never sees the poll (existing post-visibility filtering already handles this).
   - Edit a poll's question before any votes exist — confirm it saves; try editing options after a vote exists — confirm it's rejected with the French error.
   - Delete a post with a poll — confirm `polls`/`poll_options`/`poll_votes` rows cascade-delete with no FK errors.
   - Confirm posts without a poll render exactly as before (no stray empty `PollVoter` block).
   - Confirm creating a poll doesn't fire any notification beyond the existing `new_post`, and voting fires none.
